- **`-ngl 99` (GPU Layers).** Offloads all model transformer layers onto the RTX 5080's 16 GB VRAM. If a model is too large for 16 GB, lower this number (e.g., `-ngl 35`) so the remaining layers spill into your 32 GB DDR4 RAM instead of crashing with an Out-Of-Memory (OOM) error. [[1](https://www.techpowerup.com/gpu-specs/geforce-rtx-5080.c4217)]
- **`-fa on` (Flash Attention).** Enables fused CUDA attention kernels. This drastically speeds up prompt processing on Blackwell GPUs and cuts VRAM usage for long conversations.
- **`-ctk q8_0 -ctv q8_0` (KV Cache Quantization).** Compresses the context memory (Keys and Values) from 16-bit floats down to 8-bit. This cuts context VRAM usage nearly in half with virtually zero loss in output quality, allowing you to fit much larger models or longer contexts inside 16 GB. [[1](https://wiki.archlinux.org/title/Llama.cpp)]
- **`-c 32768` (Context Window).** Pre-allocates memory for 32k tokens. Because `llama.cpp` allocates the entire context buffer upfront, drop this to `8192` or `16384` if a large model is barely overflowing your 16 GB VRAM. [[1](https://wiki.archlinux.org/title/Llama.cpp)]
- **`--no-mmap` (Disable Memory Mapping).** Forces the OS to read the GGUF directly into RAM/VRAM rather than memory-mapping it from disk. On Linux with 32 GB system RAM, this prevents kernel page-cache thrashing and speeds up initial model loading.
- **(CPU Threads — for DDR4 Spillover).** Only matters when layers spill onto your CPU/DDR4. Set this to your **physical CPU core count** (not logical hyperthreads—check with `lscpu | grep "Core(s) per socket"`). Using hyperthreads saturates DDR4 memory bandwidth and slows down token generation.
- **`-b 2048 -ub 512` (Logical & Physical Batch Sizes).** Controls how many prompt tokens are processed simultaneously. Larger batches (`2048` / `512`) maximize throughput on the RTX 5080's Tensor Cores during long prompt ingestion (such as pasting codebases or documents).
